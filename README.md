# tlogs — DSH 侧边栏 Token 用量组件

> **tlogs** = **t**oken **logs**。
> 在 DeepSeek Harness 桌面端的**侧边栏页脚**常驻显示 DeepSeek 开放平台账号的 Token 用量：
> 紧凑条一眼看总计与今日，点开是完整明细，「详细数据」弹窗可按月回溯逐日与按模型明细。
> 数字经 host → 浏览器 RPC 直达侧边栏，**默认不进入模型上下文**。
> 它参与侧边栏的正常布局 —— **不是悬浮球，不是独立窗口。**

## 一、它做什么

| 形态 | 位置 | 内容 |
| --- | --- | --- |
| **紧凑条**（常驻） | 侧边栏页脚 | `总 <N> · 今日 <N> · 请求 <N>`，右侧 `↻` 手动刷新 + `▾` 展开；侧边栏收起时只留总计数字。**金额不在这里** —— 侧边栏太窄，见下方说明 |
| **展开面板**（就地撑开，不浮动） | 紧凑条下方 | 七张卡片：总消耗 / **当前项目消耗**（可点击切换项目）/ 今日 / 当周 / 当月 / **近 7 天** / **近 30 天**，每张含输入·输出·请求 + **¥ 金额** |
| **详细数据弹窗** | 浮层 | **日历**页签（可按月回溯、每格带当天金额、点某天看当天明细）+ **图表**页签（折线图 / 环形饼图 / 堆叠柱状图）+ 模型 / **供应商** / 年 / 月 / 当月按天 五个表格页签（平台口径的表含 **金额列**；「供应商」表来自本机会话日志，记录**供应商 · 模型**，含平台账单看不到的火山方舟 / 小米 / GLM / GPT） |

### 时间口径（**要和官方控制台对账，务必先读这段**）

插件有**两套**窗口口径，它们不相等，这**不是 bug**：

| 窗口 | 定义 | 对应关系 |
| --- | --- | --- |
| 今日 / 当周 / 当月 | **平台日（UTC）**：UTC 今天 / UTC 周一至今 / UTC 月 1 日至今 | 与平台日桶同口径；**北京时间 08:00 换日** |
| **近 7 天 / 近 30 天** | **滚动窗口**：含今天往前数 N 天 | **与开放平台控制台的「时间维度」同口径** |
| 历史月份边界 | **UTC** 月 | 与工作区参考 Python 脚本逐月对拍一致（见 `store/dates.ts` 的说明） |

> **展开面板里会直接写明这一行**：`统计口径：平台日（UTC）· 北京 08:00 换日`。
> 刻意把「时区」和「换日时刻」都点出来 —— 只写时区（`统计时区：UTC+08:00`）会被读成
> 「北京 0 点换日」，而平台日桶实际是 **UTC 00:00 = 北京 08:00** 换日。
>
> 为什么必须写在界面上：实测北京时间 2026-10-08 00:20 一直在跑对话，用量全部记进平台桶
> `2026-10-07`，而「今日」读到的是还没开始的 `2026-10-08` → 显示 **0**。
> 不知道日界在哪，只会当成 bug。

> ⚠️ **官方账单的日界与用量接口的日界不是同一个**（实测 + 官方文档）：
> **计费**按**北京时间日**（0 点）结算，而**用量接口** `days[]` 的日桶按 **UTC 日**
> （北京 08:00）切。两者在跨日处最多差 8 小时的用量 —— 对账时先看这一点，再怀疑插件。
> 插件**不提供「北京时间日」模式**：接口只有日粒度，一个北京日 = UTC 桶 D-1 的
> 08:00–24:00 加桶 D 的 00:00–08:00，**拆不开**；改成北京日就只能放弃与官方用量接口对账，
> 还会让「逐日取大」的双源合并失效（两路数据不再逐日可比）。

### 数据从哪来（**双路数据源**）

平台接口有两处硬限制（都是实测）：**当天数据要等平台结算** —— 北京时间 2026-10-08 当天：
12:07 平台该日桶仍是 `0`（同期本机已用 980 万 token），12:16 补到 `5.89M`、12:26 `9.72M`、
12:34 `30.2M`（与同期本机值一致），即**结算滞后约 10~30 分钟**；且**只覆盖 DeepSeek 官方通道**
—— 2026-09-18 / 09-19 本机走火山方舟共用 1.16 亿 token，平台这两天都是 `0`。
所以窗口卡片是两路数据合并出来的：

| 数据源 | 覆盖 | 时效 | 金额 |
| --- | --- | --- | --- |
| **平台账单**（`usage/amount` + `usage/cost`） | 该账号**全部设备**，仅 DeepSeek 官方通道 | 当天滞后约 10~30 分钟 | 有（官方计价） |
| **本机会话日志**（`<DSH_HOME>/sessions/**`） | 只有**本机**，但含所有供应商 | 实时 | 无 |

合并规则（`store/usage-merge.ts`）：**逐日** `max(平台, 本机 DeepSeek 通道) + 本机非 DeepSeek 供应商`。

- 取大而不是相加：平台值与本机 DeepSeek 通道值是**同一批调用的两种测量**（本机打的请求平台
  也会记），相加等于把自己打的请求算两遍。
- 本机非 DeepSeek 供应商（火山方舟 / 小米 / GLM / GPT…）平台完全看不到，才无条件相加。
- **逐日**取大而不是窗口整体取大：平台滞后只发生在当天，窗口整体取大会让昨天的多算掩盖今天的少算。

卡片右上角标注这份数字来自哪一路：`本机` / `合并`，**没有徽标 = 纯平台口径**；金额那一栏平台
尚未结算时会标 `¥结算中`（金额永远是平台计价，本机没有计价能力）。

**总消耗也走合并**：`总消耗 = 平台全部月份合计 + Σ(平台当天未结算的差额 + 本机非 DeepSeek 供应商)`。
不加这一块，用别家平台模型的那部分用量**永远不会出现在总消耗里**。

> **覆盖边界（务必知道）**：这份「本机补充」只覆盖**会话日志还在的那些天**（DSH 会清理旧日志，
> 实测当前只能回溯到 2026-09-18）。更早的旧日志已被清理，**无法回补** —— 面板与详细数据里
> 都会标注实际覆盖区间。
>
> **历史月份 / 图表 / 详细数据的「模型」表仍只用平台口径** —— 平台的月度接口按模型给总量，
> 本机日志只覆盖最近一段时间且没有计价能力。想看本机用过的**供应商与模型**（含火山方舟 /
> 小米 / GLM / GPT），去详细数据的**「供应商」页签**。
>
> 两路口径对拍过：2026-09-21~09-27 本机 DeepSeek 通道合计 `2,243.2M`，平台日桶合计
> `2,247.0M`，差 **0.2%**；2026-10-07 本机 `560.6M`、平台 `598.1M`（平台含别的设备）。
>
> 本机口径**只读**会话日志，且可用配置 `localUsage: false` 完全关闭（见「为了安全性做了什么」）。

> 典型困惑：插件「当月消耗」显示 `584M`，控制台「近 30 天」显示 `3.35B` —— 两者窗口不同，
> 并不矛盾。用**近 30 天**卡片去比控制台的「近 30 天」即可对上（实测差 <1%，差异来自数据仍在增长）。
> 例如 2026-10-07 当天：当月 = 10-01~10-07 共 7 天（其中 10-02~10-06 无用量）；
> 近 30 天 = 09-08~10-07，内含 09-22 单日 12.7 亿的峰值。

### 金额（¥）从哪来

平台有**两个**孪生接口（入参相同、返回结构同构，仅 `amount` 的含义不同）：

| 端点 | `amount` 的含义 | `biz_data` 形状 |
| --- | --- | --- |
| `GET /api/v0/usage/amount?year=&month=` | token 计数（整数） | **对象** `{total, days}` |
| `GET /api/v0/usage/cost?year=&month=` | **CNY 金额**（16 位小数） | **数组** `[{total, days, currency:"CNY"}]` |

实测要点（都已写成单测钉住，见 `test/cost.test.ts`）：

- 金额**必须**用 `toMoneyAmount`（保留小数）解析；用 token 的 `toAmount`（`Math.trunc`）
  会把所有金额吞成 `0`（踩过：整月金额全变 ¥0.00 且不报任何错）。
- `cost` 的 `days[].date` 与 `amount` 的 `days[].date` **逐个相同**，因此可与 token 逐日对齐；
  逐日金额之和与月度金额之和**完全相等**。
- `REQUEST` 的金额恒为 0（请求不计费），所以「金额」只由输入/输出的三类构成。
- 接口按模型只给**总额**（没有五类拆分），因此模型维度的金额走单独的 `modelCosts`，
  不塞进 `Money` 的某一类里（否则「输入成本」会显示成一个混合值）。

另外还会读一次 `GET /api/v0/users/get_user_summary`，给出**平台账户概览**：
充值余额 / 赠送余额 / **官方累计消费**（`total_costs`）。最后这个就是控制台账单页的数字。

> 为什么同时给「插件重算的总额」与「官方累计消费」：`usage/cost` 按月归集逐项相加，
> 与官方账单存在极小差异（实测 31 个月 ¥676.07 vs 账单 ¥675.74，约 0.05%，来自按请求四舍五入）。
> 把两个数都摆出来，你才能判断是「插件算错了」还是「精度/口径差异」。

**缺金额 ≠ 0 元。** 没有金额数据时界面**不渲染 ¥**（而不是显示 `¥0.00`），
并且快照带 `costComplete`: 历史还有月份没回补到金额时为 `false`，面板会提示「正在回补历史金额」。
金额用与逐日明细完全相同的**一次性回补**机制（`costFetched` 标记）：老的缓存行会被重抓一次，
抓完即打标记，之后不再重复请求。

### 图表页签

三张图**共享同一套控制项**，改任意一项三张图一起变：

| 控制项 | 取值 |
| --- | --- |
| **范围** | 有史以来 · 自定义（起止日期）· 今日 · 本周（周一至今）· 本月 · **近 7 天** · **近 30 天** |
| **数据源** | 平台账单（账号维度）· 任意一个本机项目 |
| **指标** | 总 Token · 输入 · 输出 · 缓存命中 · 缓存未命中 · 请求数 · **消费金额 (¥)** |
| **粒度** | 自动（≤92 天按天 / ≤3 年按月 / 更长按年）· 按天 · 按月 · 按年 |
| **口径** | 每期新增 · 累计 |

三张图通过页签内第一行的**图形子标签**（折线图 / 饼状图 / 柱状图）切换，**同屏只画一张**；
切子标签只换渲染、**不重新请求数据**。

三张图分别是：

1. **用量趋势**（折线图 + 面积填充）：所选指标随时间的走势，配 合计 / 最高 / 最低 / 均值 一行；
2. **构成占比**（环形饼图）：按模型 · 输入输出三段构成 · 按项目，构成项过多时尾部合并为「其他」；
3. **用量分布**（堆叠柱状图）：每根柱子把 **输入（缓存命中）/ 输入（缓存未命中）/ 输出** 堆起来，
   再叠一条请求数虚线（独立刻度）。

鼠标悬停时明细固定显示在图表**下方**的信息条里（不是跟随鼠标的浮层）—— 既避免浮动定位，
也避免图表高度随内容跳动。

> **指定项目的数据只到「插件启用那天」为止。** 平台账单接口是**账号维度**，没有任何项目信息；
> 宿主能给的只有「该项目累计至今」一个数。所以插件自己**每天记一条快照**，
> 趋势线靠这些快照画出来（「每期新增」= 相邻快照之差）。选项目时界面会写明当前有几条快照，
> 少于 2 条就明说「趋势需要至少跨 2 天」，而不是给一张空图让你猜。
> 快照同样只存**不可逆哈希 id + 数字**，不含 cwd、不含标签、不含任何会话内容。

其它行为：

- **自动刷新**：默认每 5 分钟（`autoRefreshSeconds`）；客户端每 60 秒回读一次快照。
- **失败兜底**：网络失败时用过期缓存显示，紧凑条出 `⚠` 角标并说明原因。
- **对话内查询（可选，默认关）**：只有 `exposeUsageToModel: true` 才注册 `query_token_usage` 工具。
  默认**不注册** —— 所以默认状态下你在对话里问用量，模型答不出来。这不是故障，是刻意的默认值。

## 二、安装

`lib/` 是**已构建产物**，DSH 直接消费它，安装过程不会帮你构建：

```bash
pnpm install
pnpm run build        # host: tsc → lib/   client: esbuild → 单文件 lib/client.js
```

> ⚠️ **desktop profile 不能用 CLI 安装**。CLI 里有一条针对 profile 名 `desktop` 的硬编码拒绝：
> `error: profile "desktop" is managed exclusively by the Electron application`。
> 请走 **设置 → 插件 → 安装**（应用内插件管理器）。

四种 spec 都支持（示例为绝对路径；相对路径会被拒绝 —— 浏览器侧不知道宿主的工作目录）：

| spec 形式 | 例子 |
| --- | --- |
| **绝对路径**（本地目录） | `D:\plugins\dsh-tlogs` |
| tarball | `D:\plugins\dsh-tlogs\dsh-tlogs-0.1.0.tgz` |
| npm 包名 | `dsh-tlogs` / `dsh-tlogs@0.1.0` |
| git | `github:<你>/dsh-tlogs` |

非 desktop 的 profile（`web` / `tui` 等）仍可用 CLI：`dsh plugin --profile web add dsh-tlogs`。

## 三、使用

1. 安装后重启 DSH，侧边栏页脚出现紧凑条。
2. `↻` 强制刷新（绕过缓存，最短 5 秒一次，且不会顺带展开面板）；点整条或 `▾` 展开面板。
3. 展开面板里点「**详细数据 ›**」开弹窗；`Esc` 或点遮罩关闭。

### 认证：凭据从哪来

DeepSeek 开放平台没有公开的用量 API，需要**网页登录态会话令牌**。按优先级：

| 顺序 | 来源 | 说明 |
| --- | --- | --- |
| 1 | 环境变量 `DEEPSEEK_PLATFORM_USER_TOKEN` | 调试用，优先级最高 |
| 2 | 配置 `platformUserToken` | ⚠️ 会明文留在 profile 配置里，**不推荐** |
| 3 | DSH 凭据系统 `TLOGS_USER_TOKEN` | 在面板里手动填写并持久化 |
| 4 | **复用 DSH 已登录账号** | **推荐，零配置**；`useAccountSession: false` 可彻底关闭 |
| 5 | 内置窗口登录 | **桌面端不可用**（宿主是 Electron 以 Node 模式启动的子进程，拿不到 `BrowserWindow`）；按钮已置灰并写明原因与替代路径 |

前 3 条是**你显式给的**，永远优先于自动来源 —— 手动粘贴的 token 不会被账号复用悄悄抢走。
「退出登录」只清第 3 项；若同时配了第 1/2 项，需要一并移除才算真正退出。

## 五、怎么实现的

**双面插件** —— 两个入口，两个运行环境：

```
exports["."]        → lib/index.js     host：取数、缓存、认证、RPC、可选工具
exports["./client"] → lib/client.js    浏览器：React 组件，注册到侧边栏页脚席位
```

- **落点**：`sidebar.footer.action`（`kind: list`、`scope: root`）—— 侧边栏页脚**唯一**的扩展席位。
  注册方式：`ctx.slots.inject(name, () => ctx.slots.register({ name, id, inject }, Component))`。
- **客户端模块格式**：`window.__ModuleLoader__.load({ id, factory })`，**`id` 必须等于包名**；
  能 `require` 的只有宿主的冻结种子表（`react` 等），**其余一律打进 bundle**（esbuild 打成单文件）。
- **不用 `position: fixed` 伪造悬浮**：紧凑条与展开面板完全参与正常布局，有测试断言守着。
  唯一的例外是**详细数据弹窗** —— 它本就该是浮层。
- **host 只用服务名，不 import 官方包**：profile 下的插件不保证能解析到 app.asar 内部的 `@deepseek-ai/*`。
  host 只把 `tools` 声明为必需，`credentials` / `connection` / `webServer` / `deepseekAccount`
  都是**可选能力**，缺失时优雅降级（这也是 web 版没有账号服务时仍能正常加载的原因）。
- **取数**：`GET /api/v0/usage/amount?year&month`。响应是**两层错误码**，两层都要检查。计算口径与权威脚本一致：

  ```
  总输入 = PROMPT_TOKEN + PROMPT_CACHE_HIT_TOKEN + PROMPT_CACHE_MISS_TOKEN
  总输出 = RESPONSE_TOKEN
  总Token = 总输入 + 总输出
  ```

  一致性由 `test/golden.test.ts`（离线逐字段对拍）与 `npm run golden`（在线端到端对拍）守着。
- **缓存**：总消耗 30 分钟、当前范围（今日/当周/当月）5 分钟；首次全量 31 个月在**后台异步**拉取，
  客户端轮询快照显示进度，不阻塞 UI。所有窗口——**包括今日/当周/当月**——一律按
  **平台日 = UTC 日**切片，日界是北京时间 **08:00**：平台接口只提供「日」粒度，本地日历日
  在数据上无法还原（详见 `src/store/dates.ts` 的说明与 `test/cost.test.ts` 的回归测试）。
- **逐日明细自愈**：历史缓存把每个月的逐日明细（`days`）一起持久化并恢复，并带 `daysFetched` 标记；
  升级后第一次刷新会把旧缓存里缺逐日明细的月份自动回补（约 29 个月 ≈ 30 秒），之后不再重复。
- **凭据投递方式随来源绑定**：网页 `userToken` → `Authorization: Bearer`；
  **账号会话凭据 → `x-dsh-auth-token`**。同一个令牌换错头一定是 `40003` —— 这是平台侧行为，不是可配置项。
- **当前项目消耗**来自 DSH 的会话投影 `tokenUsage`，按 `session.header.cwd` 分组；
  **下发给浏览器的是短哈希 id，不是完整路径**。宿主投影不提供请求次数，所以该项目卡片里 `REQUEST` 恒为 0。
- **图表不引入任何图表库**：三张图都是手写 SVG，几何换算放在 `src/client/chart-utils.ts`（纯函数，有单测，
  覆盖刻度吸附、时间轴补齐、悬停命中区间、饼图切片与弧长）。客户端 bundle 只允许 `require` 平台种子表里的
  `react`，引一个图表库就得整包打进来几百 KB —— 而真正需要的只是几条 `path` 和一个 `<rect>`。
- **图表数据走一个新端点 `tlogs.series`**：一次请求返回「范围内的逐日明细 + 逐月合计 + 模型合计 +
  累计基线 + 项目列表（+ 指定项目的快照序列）」。范围解析（本地日历、周一为一周之始、不得晚于今天）
  统一在 host 侧做，客户端只传语义化的 `range`。逐日与逐月**都**下发是有原因的：
  逐日只对抓到过 `days` 的月份存在，而月度合计始终完整 —— 按天粒度走逐日，按月/按年走月度合计，
  绝不会因为缺天而把某个季度算小。
- **落盘**：`<DSH_HOME>/tlogs/history.json`，只有用量计数 —— 不含 token、不含对话内容、不含 cwd
  （项目快照只存哈希 id 与数字，连项目 label 都不落盘，label 每次运行时从宿主重新取）。

## 六、为了安全性做了什么

| # | 措施 | 说明 |
| --- | --- | --- |
| 1 | **凭据最小化** | 账号服务在注入时被收窄成「只暴露 `getPlatformSession()`」的 facade —— `signOut()` / `rejectToken()` 这些会动你登录态的方法**结构上拿不到**（不是靠约定）。且是可选注入，`useAccountSession: false` 时连注入都不发起 |
| 2 | **只读，绝不写回** | 从不调用 `rejectToken()` —— 拿它处理用量接口的失败会把你的 DSH 登录态踢下线 |
| 3 | **不跟随重定向** | `redirect: 'manual'`。实测：跨域重定向时运行时**会**剥掉 `Authorization` 但**不剥自定义头**，`x-dsh-auth-token` 会被原样转发 —— 必须自己掐断。3xx 直接报错，且只回显目标 origin |
| 4 | **部署头白名单** | 只接受 `x-` 前缀；`Cookie` / `Origin` / `Referer` / `Host` / `x-forwarded-*` 一律丢弃。凭据头（`authorization` / `x-dsh-auth-token` / `host`）**不允许**被账号下发的 `requestHeaders` 覆盖 |
| 5 | **出口写死单主机** | 只与 `platform.deepseek.com` 通信，不读代理环境变量。**新增的两个端点也在此主机上**：`/api/v0/usage/cost`（金额）与 `/api/v0/users/get_user_summary`（余额/官方累计消费），走同一套 `buildHeaders` + `redirect: 'manual'`，凭据不出单主机 |
| 6 | **输入校验** | token 只接受可打印 ASCII（多行粘贴会被拒，且**不会被回显**进日志或错误文案）；RPC `setToken` 有 4096 字符上限 |
| 7 | **错误文案净化** | 显式抹掉令牌本体 + 压成单行（防日志注入）+ 截断；平台响应体**不再落盘** |
| 8 | **本机路径不外泄** | 下发给浏览器前把 cwd 换成短哈希；工具异常只列项目 label，不列绝对路径 |
| 9 | **端点收敛** | `export` 端点停用（它会返回含绝对路径的全量报告）；强制刷新 5 秒最小间隔（防被打成循环） |
| 10 | **删掉风险路径** | 早期「按名字盲猜宿主服务的 token getter」已整体删除 —— 那是 confused deputy：可能把推理令牌或 API Key 当平台令牌发往外部域 |
| 11 | **模型隔离** | `exposeUsageToModel` **默认 `false`**，`query_token_usage` 工具**根本不注册**；数字只走 host → 浏览器的本地 RPC |
| 12 | **仓库清洁** | 源码 / 日志 / 打包产物中**没有任何 token 字面量**（日志只写 `<redacted:len=N>`）；对拍夹具是**确定性生成的合成数据**（有断言钉住 `_synthetic: true`）；`npm run verify:secrets` 作为发布前闸门 |
| 13 | **会话日志只读、只取计数** | 第二路数据源只读 `<DSH_HOME>/sessions/**`（**从不写入**），且只提取 usage 五个计数 + provider/model 名：消息正文不读，超长的 text/reasoning/tool-call 打包行在解析前就被跳过。落盘时**只存日志路径的不可逆短哈希**（目录名里编码了工作区路径，不留），并有一致的内存/解压预算（单文件 2GB 上限）与事件循环让出。`localUsage: false` 时**连目录都不列** |

**最小化配置** —— 五个开关全关之后，这个插件只剩一件事：拿你**显式**给的 token 去取数并显示在侧边栏。

```yaml
exposeUsageToModel: false   # 默认已是 false：数字不进模型上下文
useAccountSession: false    # 不接触 deepseekAccount
enableProjectScope: false   # 不遍历会话、不读 cwd
persistHistory: false       # 完全不写磁盘
localUsage: false           # 完全不读会话日志（代价：当天/非 DeepSeek 用量会缺失）
```

> 金额功能会**多打两次请求**（`usage/cost` 与 `get_user_summary`），均在同一个平台主机上、
> 用同一份凭据、同样的只读语义。首次启用时会对历史月份做一次**一次性回补**
> （每月多一个 `usage/cost` 请求，31 个月约多 30 秒）；同月的两个请求背靠背发出，
> 因此总耗时是「月份数 ×`requestIntervalMs`」而不是两倍。金额端点失败**不会**影响该月的 token 数据。

## 七、仍存在的隐患

> 刻意分类：**A 类我改不了（DSH 架构）**，**B 类是本插件引入的取舍**，**C 类靠使用习惯**。

### A. 由 DSH 架构决定，本插件无法修复

1. **跨插件共享同一个 JS realm。** 所有插件的浏览器半都跑在同一个 `window` 里 ——
   **任何另一个插件的客户端代码都能调用 `/tlogs` 的 `setToken`（把用量查询指向别人的账号）
   或 `logout`（清掉令牌并销毁历史缓存）。** 本插件只能收敛端点，**无法阻止同 realm 的读取**。
   装的第三方插件越多，这个面越大。
2. **`.credentials.yaml` 里的凭据是「拿来即用」形态。** 实测：把文件里那条 grant 的值
   **未经任何解密**直接当 `x-dsh-auth-token` 打接口，就取到了真实数据。
   含义是 —— **任何以你用户身份运行的进程都能读到可用凭据**（Windows ACL 只挡别的用户）。
   你手动粘贴的 `TLOGS_USER_TOKEN` 也以同样形态落在那里。存储方式由 DSH 决定，插件改不了。
3. **本机回环服务 + 会话 Cookie。** DSH 的「会话 Cookie + Host/Origin 校验」围栏能挡 CSRF 与
   DNS rebinding，但本机上一个拿到该 Cookie 的恶意进程可以调 RPC。这属于 DSH 的威胁模型。
4. **依赖供应链。** 本插件唯一的运行时依赖是 `schemastery`，但 profile 的 pnpm registry
   指向 `registry.npmmirror.com`（第三方镜像）。**镜像被投毒 = 安装期注入代码**，影响所有包。

### B. 本插件引入、已缓解但有剩余

5. **账号会话凭据在进程内存驻留（最长 60 秒）。** 这是「性能 vs 凭据驻留时间」的取舍 ——
   不缓存就要每秒 1~2 次账号服务调用。`useAccountSession: false` 可彻底消除这条路径。
6. **面板仍会显示项目 label**（末两级路径或工作区标题）。这是功能必需，否则你分不清是哪个项目。
   连这个都不接受，就设 `enableProjectScope: false`。
7. **平台错误文案会进宿主日志。** 已做单行化 + 截断 + 抹掉令牌本体，但平台返回的文本本身
   仍会写进日志 —— 这是「可诊断性」的代价，我选择不静默丢弃它。
8. **RPC 没有插件自有鉴权。** 保护全部来自 DSH 连接层（见 A1 / A3）。我**故意不自己加一层**：
   自定义共享密钥或密码学引入的出错风险，大概率高于它挡住的威胁。
9. **`lib/` 被手改无法检测。** `lib/` 是被提交且**直接运行**的产物，目前没有任何校验能发现
   「绕过 `src/` 只手改 `lib/`」。**这是已知缺口，不是已完成项** —— 彻底的做法是把 `src/`
   构建到临时目录再与 `lib/` 逐文件比对，但客户端 bundle 的输出路径由 esbuild 写死，
   硬加比对容易产生假阳性，反而让这条检查失去可信度。
10. **项目快照只从「插件启用当天」开始积累。** 这不是实现偷懒：平台账单接口没有项目维度，
   宿主的 `tokenUsage` 投影也只给累计值，没有任何可回溯的按天来源。副作用是换上这个版本的第一天，
   「指定项目」的折线只有 1 个点。`enableProjectScope: false` 时快照完全不会记录。

### C. 使用习惯层面（插件管不了）

10. **你自己在对话里贴数字或截图** → 照样进模型上下文。插件能控制工具，控制不了这个行为。
11. **把 token 填进 `platformUserToken`** → 它会明文出现在 profile 配置文件里，
    比凭据库更容易被看到或误提交进版本库。
12. **参考脚本里的明文令牌。** 工作区那份权威 Python 脚本把真实 `USER_TOKEN` 写死在源码里。
    本项目已做的处理：`.gitignore` 排除 `deepseek_python_*.py`、在线对拍不再从它抓令牌（只认环境变量）。
    **但让该会话失效并轮换令牌，只能你在平台侧做。**

## 八、配置项

完整模板见 [cordis.patch.yml](cordis.patch.yml)。常用项：

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| `exposeUsageToModel` | `false` | 是否注册对话内查询工具（**工具的返回值就是模型上下文**） |
| `useAccountSession` | `true` | 是否复用 DSH 已登录账号的会话凭据 |
| `localUsage` | `true` | 是否读会话日志作为第二路数据源（见「数据从哪来」） |
| `localUsageScanDays` | `32` | 本机口径回溯天数（覆盖「近 30 天」窗口） |
| `enableProjectScope` | `true` | 「当前项目消耗」卡片（会遍历会话读 cwd） |
| `persistHistory` | `true` | 是否把历史写到 `<DSH_HOME>/tlogs/history.json` |
| `autoRefreshSeconds` | `300` | 定时自动刷新间隔（秒），`0` = 关闭 |
| `cacheTTL.total` / `cacheTTL.current` | `1800` / `300` | 总消耗 / 当前范围缓存（**秒**） |
| `startYear` / `startMonth` | `2024` / `4` | 首次全量的历史起点 |
| `requestIntervalMs` | `1000` | 月度请求间隔（**毫秒**） |
| `numberFormat` | `short` | `full`（千分位）\| `short`（K/M/B）；金额另有一套（`¥172.48` / `¥1.23万`） |
| `cacheDir` | `''` | 留空 = `<DSH_HOME>/tlogs` 或 `$TLOGS_CACHE_DIR` |
| `compactMetrics` | `[total, today]` | 紧凑条放哪些指标 |

`compactMetrics` 可选值：`total` `today` `week` `month` `last7` `last30`（token 口径）
以及 `cost_total` `cost_today` `cost_last7` `cost_last30`（对应的 **¥**，用 `unit: 'money'` 走金额格式化）。

**默认不放金额。** 侧边栏页脚只有约 250px 可用宽度：四个指标（总 / 金额 / 今日 / 请求）
会把标签挤成认不出的碎片 —— 实测紧凑条变成 `8.9B · ¥678.87 · ↖561M · ⚡2.4K`，
数字还在但看不懂。所以金额移到**展开面板的卡片**和**详细数据**里。
确实想在小窗看金额，把 `cost_total` 显式加进去即可；指标行挤不下时会**整项换行**
（不再压缩标签），最多让紧凑条高出一行。

环境变量：`DEEPSEEK_PLATFORM_USER_TOKEN`（显式 token，优先级最高）、`TLOGS_CACHE_DIR`（缓存目录）、
`DSH_HOME`（本机口径的会话日志根目录 = `<DSH_HOME>/sessions`）。

## 九、开发

```bash
pnpm run check          # 密钥闸门 + typecheck + build + 全部测试
pnpm run golden         # 在线端到端对拍（需要 DEEPSEEK_PLATFORM_USER_TOKEN，约 90 秒）
pnpm run verify:dsh     # 用本机 DSH 的真实解析器校验插件声明（含负例对照）
pnpm run build:preview  # 重新生成 docs/embed-preview.html 静态预览
```

> `test/golden.test.ts` 在找不到外部 Python 参考脚本时会 **skip 而不是 fail** —— 那是 gitignore 的
> 外部输入（源码里含明文令牌），新克隆的仓库里不会有它。用 `TLOGS_REFERENCE_SCRIPT=<路径>`
> 可以把它指过去，既不必把带令牌的文件放回仓库，也能保留这条防线。

`docs/embed-preview.html` 是**静态预览页**，用真实组件与真实 CSS 经 `react-dom/server` 渲染，
用于核对布局与两种主题下的可读性 —— 它不是应用内截图。
